Add a wide grouped sum of int pairs

`groupedSum` on `DistCollection[(Int, Int)]` runs `ColumnPipeline.sumByKey` and folds the `Int64` group sums into one `Long`.

A source, `filterKeys`, or `filterValues` of int pairs stays on that kernel and is not decoded. Empty input returns 0. Null keys stay dropped. Two `Int.MaxValue` values for one key sum to `Int.MaxValue.toLong * 2`, including after `filterValues`. `ColumnarPlanner.partitioning` stays `Some(Columnar)` for those shapes.

`reduceByKey` is unchanged and still wraps at `Int`. There is no new plan node and no `(Int, Long)` group result. A shape the planner refuses sums through the row engine. Pair batches stay two columns wide; `ColumnReduce.sumInt64` reads the measure column, so the width-1 `sumInt32` check does not apply.

`make lint`, `make test-lint`, and `make test` passed (456 tests).
