Refuse non-default join strategies on the columnar path

## Summary

`ColumnarPlanner.lower` accepts a join only when its strategy hint is absent or `ShuffleHash`. An explicit sort-merge or broadcast hint returns `None`. `partitioning`, `tryRun`, `tryCount`, `trySumInt`, `trySumDouble`, `tryTake`, and `tryGroupedSum` follow that refusal, so those plans run on the row path. A join with no hint, or with an explicit shuffle-hash hint, still lowers to the same `HashJoin(Exchange, Exchange)` tree.

The row path already dispatches on the hint. `Broadcast` runs the broadcast hash join, `ShuffleHash` runs the shuffle hash join, and `SortMerge` runs the existing per-partition task. That task orders keys by `hashCode` and then groups by equality. It is not a typed sort-merge, and this change does not add one. An unhinted join on the row path still auto-selects a strategy from input size. The columnar path does not implement sort-merge or broadcast.

The contract moves those two shapes from the mismatch list into the excluded fixtures. The mismatch count is 1: the fused pair-map layout. Excluded fixtures are 45. Every excluded fixture, including these joins, asserts that `lower` and each action gate agree on the row path.
