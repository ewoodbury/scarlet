Keep keys, values, and int mapValues on the columnar path

`keys`, `values`, and int `mapValues` on `(Int, Int)` stay on the columnar path.

`KeysOp` and `ValuesOp` lower to one int column by sharing the published column object (`ColumnBatches.takeColumn`). A published column is not mutated, so the view is correct and cheaper than copying the values and the validity bitmap. `sum` does not build that view at all: it reads ordinal 0 or 1 inside the morsel loop (`ColumnReduce.sumInt32At`). `collect` is the path that wraps the shared column in a one-column batch.

`MapValuesOp` lowers only when a declared `apply` or `apply$mcII$sp` returns primitive `int` and takes one primitive `int`, and no declared `apply` returns some other reference type. That check does not call the function. A `String` or `Long` result stays rejected and runs on the row engine. The planner does not box or widen. `mapValues` returns `(K, B)`, and `sum` exists for `Int` and `Double`, so the int sum is `.mapValues(...).values.sum`. That sum applies the `Int => Int` function in the morsel loop and does not write a value column.

`filterKeys`, `filterValues`, and `reduceByKey` are unchanged. There is no new `Plan` node. `Int32Pipeline` is unchanged.

`ColumnMetrics` counts published batches and morsel visits only while armed. It is disarmed by default. The projection tests arm it around one sum: one source-copy batch and one morsel visit. `.mapValues` to `String` or `Long` has an empty partitioning and records no batches.

`make lint`, `make test-lint`, and `make test` passed (467 tests).
