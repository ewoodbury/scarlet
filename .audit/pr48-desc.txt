Restore pair-length checks and grouped-sum null-key parity

## Summary

- `IntPairArrays.fromOwned` and raw `intPairs(Array, Array)` reject unequal key and value arrays with one shared message, before a primitive encode is counted. The row count then comes from that shared length.
- Parallel `drain` notes a visit before its only worker call, including a morsel taken from another worker's deque. A run of several morsels with parallelism above 1 reports `visitCount` equal to the morsel count.
- The grouped-sum row fallback adds a value only when the key and the value are both present. Grouped-sum encode records a null component as absent, so the columnar total and the row total match. Other actions still use the unboxing pair fill.
- Each accepted wide grouped-sum shape asserts that `ColumnarPlanner.tryGroupedSum` is defined.
- The two `mapValues` casts that follow the `Int => Int` descriptor check carry a suppression and a comment. They are named erasure boundaries.
- `TestColumnBatch` disarms `ColumnMetrics` in `afterEach`.
- `sumMappedInt32` on a pair column with null values matches the sum of the present values, and the mapper is not called for a null slot.
- `DistCollection` and `ColumnarPlanner` import the core names they use. OrganizeImports keeps six names explicit and still coalesces seven or more. `DAGScheduler` keeps its existing `core.*` import.
- `ints` and `float64s` copy an `ArraySeq` or fill any other iterable from the outer match.
- `IntArrays` and `DoubleArrays` document `private[scarlet]`. A primitive encode also counts raw `intPairs(Array, Array)`.

This branch also seals primitive partitions behind `IntArrays`, `DoubleArrays`, and `IntPairArrays`. Encode copies those arrays into columns and does not adopt them.

Results are unchanged except the grouped-sum null-key total, which now agrees on both paths.
