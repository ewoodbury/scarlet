Add a dense grouped-sum path

## Summary

A grouped partial takes a direct-index sum when the present keys in that morsel form a bounded range. The span is `max.toLong - min.toLong + 1`, compared with a cap of 4 MiB divided by `parallelism * 9` bytes per slot. A span that does not fit, including `Int.MinValue` together with `Int.MaxValue`, uses the hash table.

Each slot is a sum and one flag byte with two bits. The group bit means the key was seen. The value bit means a value was added. A null value sets the group bit and leaves the sum null. A filtered sum sets both bits only when a value is kept, so a key whose rows are all dropped stays absent.

`MapPair`, and any other `PairStep` chain that can rewrite the key, stays on the hash path. Value-only keeps use the direct index. The dense path emits keys in ascending order. The hash path still emits first-seen order. Grouped sums are compared as maps.

A present non-negative key in `[0, 65536)` skips the min/max pass and is indexed by the key. A contiguous span that starts at zero reuses one identity key array. Callers only read it. Anything wider, and a prefix miss that classifies as wide, falls back to the hash table.

## Study

Harness: 1e7 rows, 1024 groups, batch size 8192, 1222 morsels. Checksum `49999995000000`. Nearest-rank p50 over 41 samples. The before column is the in-place hash partial on this harness. The after columns are two runs of this branch.

| partial stage | before | after, run 1 | after, run 2 |
| --- | ---: | ---: | ---: |
| p50, 1 thread | 36.70 ms | 11.677 ms | 11.748 ms |
| p50, 4 threads | 11.79 ms | 4.088 ms | 3.912 ms |
| allocation, 1 thread | 16.90 MB | 11.68 MB | 11.70 MB |

Both runs are under the 12 ms and 6 ms partial gates. The partial stage records 1222 batches and 1222 visits.

## Tests

`make lint`, `make test-lint`, and `make test` (563 tests) are green.

`TestDenseGroupedSum`:

- reject the full `Int` domain and accept a subrange
- skip null keys when measuring the range
- ignore keys outside the scanned rows
- derive the cap from 4 MiB of 9-byte slots
- index a range of `denseCap` and hash a range one past it
- match the hash table, including a null sum and a rejected key
- sum negative keys and a window that does not start at zero
- hash `Int.MinValue` together with `Int.MaxValue`
- keep `MapPair` on the hash path
- index a value filter and hash a pair map through the pipeline
- drop the previous range when the next range reuses the index
- omit a key that only the previous morsel saw
- fail a key that sits outside the classified window
- sum a single-row morsel and publish an empty partial for a zero-row batch
- count one visit per morsel when the index is used

`TestGroupedSumKernel` expects ascending keys from the dense partial (`1`, `4`) and first-seen order from the hash aggregate (`4`, `1`). The sums are the same map.
